# XavierOS

**Версия 0.1.3** · Экспериментальная любительская ОС x86_64 на Rust.

XavierOS — небольшое ядро `no_std`, загружаемое через Limine. Проект предназначен для обучения и экспериментов в QEMU, а не для повседневного или производственного использования.

## Возможности

- Limine, консоль во framebuffer, PS/2-клавиатура, прерывания PIC/PIT и обработчики исключений IDT.
- PMM, HHDM и heap ядра.
- ATA PIO, записываемая XVDISKFS на постоянном диске QEMU, read-only initramfs XVRFS и VFS.
- Прототип кооперативного планировщика и переключения контекста.
- Локальные пользователи, хэши паролей PBKDF2-HMAC-SHA256, ограничение повторных попыток входа и базовые проверки доступа к путям в shell.
- История команд, Tab-автодополнение, редактирование строки, `FSCK`, `DF`, `HEALTH` и `SYSINFO` в стиле neofetch.

## Сборка и запуск

Нужны Rust через `rustup`, Python 3.10+, QEMU и инструменты хоста. В macOS/Linux установите C-компилятор и `xorriso`; в Windows скрипт сборки может подготовить поддерживаемые вспомогательные инструменты.

```text
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
python run.py
```

ISO создаётся в `build/xavieros.iso`. `run.py` подключает постоянный 16-МиБ диск `data/xavieros-disk.img`. Команда `python run.py --reset-disk` пересоздаёт его и удаляет все файлы и аккаунты.

В оболочке используется тонкий вертикальный курсор ввода, история команд и автодополнение по Tab.

## Пользователи

На чистом диске временная сессия `live` может создать первого пользователя, который становится администратором:

```text
USERADD alice
LOGIN alice
WHOAMI
HOME
PASSWD
```

При вводе пароль скрыт. Допускаются 8–63 печатных ASCII-символа с учётом регистра; в базе сохраняются salted-хэши PBKDF2-HMAC-SHA256. После трёх неудачных входов вводится ограничение на пять секунд. Создание аккаунтов и смена пароля требуют CPU RDRAND; `run.py` использует `-cpu max`, чтобы обычно включать эту возможность в QEMU TCG. У аккаунтов, созданных в 0.1.2, прежняя соль сохранится до однократной смены пароля через `PASSWD`. Максимум — восемь аккаунтов. Обычный пользователь ограничен проверками shell своим каталогом `/DISK/HOME/<имя>`.

## Команды

- **Редактирование:** Left/Right, Home/End, Delete, Backspace, Ctrl+U (очистить строку), Ctrl+C (отменить ввод).
- **История:** Up/Down листают 16 последних команд; Tab дополняет имена команд и доступные пути.
- **Диск:** `DISK`, `DF`, `FSCK` (проверка метаданных только для чтения), `LS`, `CAT`, `WRITE`, `MKDIR`, `RM`.
- **Система:** `SYSINFO`, `HEALTH`, `UPTIME`, `MEM`, `HEAP`, `PMM`, `IRQ`, `TASKS`, `SELFTEST`.
- **Аккаунты:** `USERADD`, `USERS`, `LOGIN`, `LOGOUT`, `WHOAMI`, `PASSWD`, `HOME`.

`SYSINFO` сохраняет стиль neofetch: ASCII-логотип X и сведения об ОС/ядре, CPU, дисплее, пользователе, времени работы, RAM/PMM, heap, диске и планировщике. `HEALTH` показывает состояние подсистем, но не является аудитом безопасности. `FSCK` проверяет суперблок, метаданные, дерево каталогов и пересечение областей файлов, не записывая исправления.

## Ограничения

- Учётные записи и проверки доступа экспериментальны; команды работают в ring 0. Полноценной изоляции пользовательских процессов нет. Не используйте реальные или повторно используемые пароли.
- Генерация соли работает по принципу fail-closed: если RDRAND недоступен, создание пользователя и смена пароля запрещаются вместо применения предсказуемого TSC/таймера.
- XVDISKFS не имеет журнала и не защищена от аварийного выключения. `FSCK` только проверяет повреждения и ничего не чинит автоматически. Используйте тестовые образы дисков.
- Планировщик кооперативный. User Mode, изоляция адресных пространств, сеть, рабочий стол и широкая поддержка физического оборудования не реализованы.
- Поддерживаемая среда разработки — QEMU; физическое оборудование не проверено.
