# XavierOS

**Экспериментальная операционная система x86_64 на Rust.**

Ядро `no_std` с загрузкой через Limine, framebuffer-консолью, управлением памятью, диагностикой исключений процессора, клавиатурными прерываниями, встроенной файловой системой и небольшой записываемой файловой системой на виртуальном диске QEMU.

## О проекте

XavierOS — учебный hobby-проект для изучения загрузки компьютера и устройства ядра. Система написана на Rust без стандартной библиотеки (`#![no_std]`) и сейчас рассчитана на `x86_64-unknown-none`. После загрузки появляется собственная текстовая консоль; рабочего стола пока нет.

Ветка `main` содержит исходники подготовленного maintenance-обновления `0.1.1`. **Считать его готовым к выпуску можно только после успешной сборки ядра и тестов в QEMU.** Уже опубликованный релиз `v0.1.0` не изменяется.

## Возможности

- Загрузка через Limine и сборка ISO для BIOS/UEFI.
- Консоль на framebuffer и собственная оболочка команд.
- Чтение карты памяти Limine, HHDM, bitmap PMM и heap ядра размером 1 МиБ.
- IDT и диагностика исключений процессора, включая регистры и CR2 при page fault.
- Настройка legacy PIC/PIT, счётчик тиков и ввод с PS/2-клавиатуры через IRQ1 и ограниченный кольцевой буфер.
- Встроенная read-only initramfs XVRFS v1.
- ATA PIO для primary IDE master в QEMU и записываемая XVDISKFS v1 по пути `/DISK`.
- VFS-маршрутизация между встроенными файлами и диском.
- Прототип кооперативного переключения контекста задач с отдельными стеками; вытесняющей многозадачности пока нет.
- Самотесты памяти, heap, прерываний, файловых систем и задач.
- Python-инструменты сборки и запуска для Windows, macOS и Linux.

## Обслуживающие изменения 0.1.1

- Исправлено выделение места при перезаписи файла: старый диапазон остаётся занятым до фиксации новых метаданных, поэтому подготовка замены не должна перезаписывать прежнее содержимое.
- Усилена проверка метаданных XVDISKFS: корневой записи, полей хранения файлов, цепочек родительских каталогов, глубины дерева и диапазонов данных.
- Усилена проверка освобождения памяти в heap: границы, заголовки аллокаций, пересечения со свободными блоками и распространённые случаи повторного освобождения.
- ATA-драйвер проверяет завершение чтения/записи после передачи данных.
- Загрузка архивов Limine/xorriso не следует ссылкам из архива; отклоняются path traversal, специальные файлы и дубли путей без учёта регистра.
- Добавлены локальные host-тесты для Python-инструментов, генерации initramfs и подготовки релиза.

Это меры укрепления надёжности, а не аудит безопасности и не гарантия целостности файловой системы при сбое питания.

## Сборка и запуск

### Требования

- Python 3.10+.
- Rust (`rustup` и `cargo`): [rustup.rs](https://rustup.rs/).
- QEMU с `qemu-system-x86_64` в `PATH`.
- `xorriso` в `PATH`. В Windows скрипт может загрузить запасной комплект xorriso.
- На macOS/Linux — C-компилятор (`cc`, Clang или GCC), если для сборки утилиты Limine не найден готовый исполняемый файл.
- Интернет при первой сборке для загрузки Limine и, при необходимости, xorriso.

### Подготовка target

В корне проекта:

```text
python setup.py
```

### Сборка ISO

```text
python build.py --clean
```

Результат: `build/xavieros.iso`.

### Запуск в QEMU

```text
python run.py
```

При первом запуске создаётся постоянный виртуальный диск размером 16 МиБ: `data/xavieros-disk.img`. Файлы в `/DISK` переживают обычные перезапуски и пересборки. Образ исключён из Git.

**Разрушающие команды:** `python run.py --reset-disk` пересоздаёт образ диска, а команда XavierOS `FORMAT DISK` стирает файловую систему. Используй только тестовый виртуальный диск, созданный скриптом; не подключай реальный или ценный диск.

## Проверки

```text
python -m compileall -q build.py run.py setup.py mkinitramfs.py package_release.py tests
python -m unittest discover -s tests -v
python mkinitramfs.py --output build/initramfs-check.xfs
cargo build --release --target x86_64-unknown-none
```

Затем запусти QEMU и пройди smoke-test из [TESTING.md](TESTING.md). Host-тесты не запускают QEMU и не подтверждают поддержку физического оборудования, поэтому сборку ядра и runtime-проверки нужно выполнить локально.

## Основные команды

| Команды | Назначение |
|---|---|
| `HELP`, `ABOUT`, `VERSION` | Справка и версия |
| `SYSINFO`, `INFO`, `CPU`, `MEM`, `PMM`, `HHDM`, `HEAP` | Система и память |
| `IDT`, `IRQ`, `TIME`, `DIAG` | Прерывания и диагностика |
| `LS`, `DIR`, `CAT`, `STAT`, `PWD`, `FSINFO`, `FSTEST` | Файлы и каталоги |
| `DISK`, `DINFO`, `MKDIR`, `WRITE`, `TOUCH`, `RM` | Записываемый `/DISK` |
| `FORMAT DISK` | **Стирает** содержимое тестового диска |
| `TASKS`, `TASKTEST` | Кооперативные задачи |
| `SELFTEST` | Самотесты подсистем |
| `CALC`, `ECHO`, `CLEAR`, `REBOOT`, `HALT` | Утилиты оболочки |
| `TRAP` | Намеренно вызвать invalid opcode; QEMU остановится |

Актуальный список команд в конкретной сборке показывает `HELP` внутри XavierOS. Это собственная оболочка, а не POSIX shell.

## Статус и ограничения

XavierOS экспериментальная; она предназначена для обучения и тестирования в виртуальной машине, а не для повседневной работы или production-нагрузок.

- Физическое оборудование и все варианты BIOS/UEFI не проверены; основная цель тестирования — QEMU.
- ATA-драйвер рассчитан на legacy PC/PIIX IDE и синхронный LBA28 PIO.
- XVDISKFS — небольшой собственный формат, **не защищённый от сбоев питания**. При ошибке записи метаданные могут оказаться несогласованными; инструменты восстановления ещё не реализованы.
- PMM, heap и планировщик рассчитаны на одно ядро CPU; архитектура не SMP-safe.
- Планировщик кооперативный. Нет вытесняющей многозадачности, изоляции процессов, user mode, ELF-загрузчика, сети или рабочего стола.
- Нет общей системы блокировок, безопасной для IRQ. Обработчики прерываний не должны выделять heap-память или обращаться к диску.
