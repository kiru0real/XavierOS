**Небольшая экспериментальная хобби-ОС для x86_64, написанная на Rust.**

## О проекте

XavierOS — небольшая хобби-операционная система для изучения разработки ядра. Ядро написано на Rust без стандартной библиотеки (`#![no_std]`) для `x86_64`. Загрузка выполняется через Limine; проект предназначен для экспериментов в одноразовой виртуальной машине, а не для повседневного или промышленного использования.

## Возможности

- Загрузка через Limine, framebuffer-консоль, клавиатура PS/2, исключения IDT, прерывания PIC/PIT и serial-диагностика.
- Карта памяти Limine, bitmap PMM, HHDM, heap ядра и прототип кооперативного переключения задач.
- Виртуальный диск ATA PIO, записываемая XVDISKFS, read-only initramfs XVRFS и слой VFS.
- Экспериментальные локальные аккаунты с salted PBKDF2-HMAC-SHA256-хэшами и базовыми ограничениями домашних каталогов на уровне оболочки.
- Редактирование строки ввода, история команд, Tab-автодополнение и `SYSINFO` в стиле neofetch с логотипом X.
- Сеть QEMU Intel E1000: DMA-кольца, ARP, IPv4, ICMP `PING`, DNS A-запросы, DHCP-клиент и UDP NTP-клиент.
- Экспериментальный синхронный TCP/HTTP-клиент с ограниченными повторами, редиректами, `Content-Length` и chunked-ответами.
- `HTTPGET` для просмотра ограниченного ответа и `FETCH` для сохранения полного небольшого HTTP-тела на диск.
- `NETSTAT` и `NETCHECK` для сетевых счётчиков и проверки соединения.
- Команды времени `DATE`, `TIME`, `DATETIME`, `TIMEZONE`, `NTP`.
- Постоянная конфигурация с контрольной суммой и чередованием слотов; команды `CONFIG`/`SETTINGS` и диагностический отчёт `REPORT`.
- Более безопасный `FETCH`: запись во временный файл и переименование только после получения полного ответа.

## Сборка и запуск

### Требования

- Windows 10/11, Linux или macOS.
- Rust через `rustup`, включая target `x86_64-unknown-none`.
- Python 3.10+ и QEMU (`qemu-system-x86_64`).
- На Linux/macOS нужны C-компилятор и `xorriso`; на Windows скрипт может подготовить поддерживаемые вспомогательные инструменты.
- При первой сборке может понадобиться интернет для скачивания недостающих инструментов.

Из корня репозитория:

```text
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
python run.py
```

Сборка создаёт `build/xavieros.iso`. `run.py` подключает постоянный 16-МиБ диск `data/xavieros-disk.img`, виртуальную Intel E1000 через user-mode NAT и задаёт виртуальным часам базу UTC. **`python run.py --reset-disk` удаляет файлы, аккаунты и сохранённые настройки.**

## Команды консоли

Оболочка XavierOS небольшая; это не POSIX shell и она не запускает команды Linux.

| Команда | Описание |
|---|---|
| `HELP`, `ABOUT`, `VERSION`, `BANNER` | Справка, описание, версия и логотип |
| `SYSINFO`, `INFO`, `CPU`, `MEM`, `PMM`, `HHDM`, `HEAP` | Сведения о системе и памяти |
| `HEALTH`, `DIAG`, `SELFTEST`, `IDT`, `IRQ`, `UPTIME`, `REPORT` | Диагностика и отчёт |
| `LS [PATH]`, `CAT PATH`, `STAT PATH`, `PWD`, `FSINFO`, `FSTEST` | Просмотр файлов |
| `WRITE PATH TEXT`, `TOUCH PATH`, `MKDIR PATH`, `RM PATH`, `DF`, `FSCK`, `DISK` | Диск и файловая система (`FSCK` — проверка метаданных только для чтения; данные не исправляются) |
| `USERADD`, `LOGIN`, `LOGOUT`, `WHOAMI`, `USERS`, `PASSWD`, `HOME` | Экспериментальные аккаунты |
| `CONFIG`, `SETTINGS` | Показать сохранённые настройки |
| `CONFIG SET TIMEZONE +0300` | Задать ручное смещение часового пояса |
| `CONFIG SET NTP time.cloudflare.com` | Указать NTP-сервер |
| `CONFIG SET NETWORK DHCP` / `STATIC` | Выбрать DHCP или статический профиль QEMU |
| `CONFIG SET TIMEOUT 10` | Задать сетевой тайм-аут в секундах (1–120) |
| `CONFIG SAVE`, `CONFIG RESET` | Сохранить настройки или вернуть значения по умолчанию |
| `REPORT SAVE /DISK/HOME/USER/REPORT.TXT` | Сохранить отчёт в доступный путь на диске |
| `NET`, `DHCP`, `NETSTAT`, `NETCHECK` | Состояние сети и диагностика |
| `PING HOST [COUNT]` | ICMP-проверка, 1–8 запросов |
| `HTTPGET http://HOST/PATH` | Показать ограниченный HTTP-ответ |
| `FETCH http://HOST/PATH /DISK/PATH` | Сохранить полностью полученное HTTP-тело |
| `DATE`, `TIME`, `DATETIME`, `TIMEZONE`, `NTP [SERVER]` | Время и NTP-синхронизация |

### Примеры

```text
CONFIG
CONFIG SET TIMEZONE +0300
CONFIG SET NTP time.cloudflare.com
CONFIG SET NETWORK DHCP
CONFIG SET TIMEOUT 10
CONFIG SAVE
NETCHECK
PING example.com 2
HTTPGET http://neverssl.com/
FETCH http://example.com/ /DISK/HOME/alice/example.html
REPORT
REPORT SAVE /DISK/HOME/alice/REPORT.TXT
```

В примерах замени `alice` на имя своего постоянного пользователя. Первый постоянный аккаунт является администратором. Изменение конфигурации требует прав администратора. Аккаунты экспериментальные: команды по-прежнему работают в ring 0 и не обеспечивают изоляцию процессов.

`FETCH` принимает только HTTP без TLS, пишет только под `/DISK`, проверяет доступ активного пользователя, отказывается перезаписывать существующий путь и сначала сохраняет тело во временный файл, который переименовывается после завершения ответа. Буфер ограничен 16 КиБ. Загруженное содержимое не является доверенным.

## Уведомление о новых версиях

Автоматическая проверка новых GitHub-релизов пока не реализована. Для неё необходима поддержка HTTPS/TLS: GitHub Releases API требует HTTPS, а XavierOS пока не умеет проверять TLS-соединения. Система не будет отправлять небезопасные HTTP-запросы для получения данных обновления. После реализации TLS с проверкой сертификатов можно добавить неблокирующее уведомление при старте, сравнивающее установленную версию с последним релизом — без автоматической загрузки или установки.

## Статус и ограничения

- XavierOS экспериментальна и рассчитана на эмулируемую QEMU Intel E1000. Физическое оборудование не проверено.
- Аккаунты не являются полноценной границей безопасности: изоляция User Mode отсутствует. Не используй реальные или повторно используемые пароли.
- TCP — экспериментальный синхронный HTTP-клиент, а не полноценный стек. Контроль перегрузки, постоянные соединения, надёжное восстановление после потери данных, HTTPS/TLS, IPv6 и физические сетевые карты не реализованы.
- Продление DHCP-аренды, автоматическое определение часового пояса/местоположения, правила летнего времени и сохранение синхронизированного времени после перезагрузки пока отсутствуют. Смещение времени, NTP-сервер, режим сети и тайм-аут можно сохранять в конфигурации.
- XVDISKFS не журналируется и не защищена от аварийного выключения. Два слота конфигурации с контрольной суммой снижают риск потери предыдущих настроек, но не делают файловую систему полностью crash-safe. `FSCK` только проверяет данные.
- Планировщик кооперативный. Графическая оболочка, загрузчик пользовательских ELF и изоляция виртуальных адресных пространств отсутствуют.

Используй одноразовые виртуальные диски и делай резервные копии. `data/xavieros-disk.img` — локальные данные, их нельзя коммитить в Git.

## Структура проекта

```text
XavierOS/
├── .cargo/             # Конфигурация bare-metal target и linker
├── src/                # Ядро, память, хранилище, аккаунты, часы, конфиг и сеть
├── tests/              # Host-side и регрессионные проверки
├── rootfs/             # Содержимое read-only initramfs XVRFS
├── Cargo.toml
├── build.py            # Сборка ядра и ISO
├── run.py              # Запуск QEMU с диском и E1000 NAT
├── mkinitramfs.py      # Сборка XVRFS initramfs
├── package_release.py  # Упаковка ISO и checksum-файла
├── CHANGELOG.md
├── LICENSE
├── README.md
└── README.ru.md
```

Сгенерированные папки `target/`, `build/`, `tools/`, `dist/`, кэш Python и постоянный образ диска не являются исходниками и не должны попадать в репозиторий.
