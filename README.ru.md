## О проекте

XavierOS — небольшая хобби-ОС для изучения разработки ядра. Ядро написано на Rust без стандартной библиотеки (`#![no_std]`) и предназначено для архитектуры `x86_64`. Загрузка выполняется через Limine. Проект рассчитан на эксперименты в виртуальной машине, а не на повседневное или промышленное использование.

## Возможности

- Загрузка через Limine, framebuffer-консоль, клавиатура PS/2, обработчики исключений IDT, прерывания PIC/PIT и диагностика через serial.
- Карта памяти Limine, физический аллокатор страниц PMM, HHDM, heap ядра и прототип кооперативного переключения задач.
- Виртуальный диск ATA PIO, записываемая XVDISKFS, read-only initramfs XVRFS и небольшой слой VFS.
- Экспериментальные локальные аккаунты с salted PBKDF2-HMAC-SHA256 хэшами паролей и базовыми ограничениями доступа к домашним каталогам на уровне shell.
- Редактирование строки ввода, история команд по стрелкам вверх/вниз, автодополнение Tab и `SYSINFO` в стиле neofetch с логотипом X.
- Сеть через эмулируемую QEMU Intel E1000: DMA-кольца, ARP, IPv4, ICMP `PING`, DNS A-запросы, DHCP и NTP через UDP.
- Экспериментальный однократный TCP-клиент для простых HTTP/1.0-запросов — команда `HTTPGET`.
- Сетевые команды `NET`, `NETSTAT`, `NETCHECK` и счётчики Ethernet-кадров.
- Команды системного времени `DATE`, `TIME`, `DATETIME`, `TIMEZONE` и `NTP`.

## Сборка и запуск

### Требования

- Windows 10/11, Linux или macOS.
- Rust через `rustup`, включая target `x86_64-unknown-none`.
- Python 3.10 или новее.
- QEMU (`qemu-system-x86_64`).
- C-компилятор и `xorriso` на Linux/macOS; скрипт сборки может подготовить поддерживаемые вспомогательные инструменты на Windows.
- Доступ к интернету при первой сборке, если инструменты Limine и Windows-версия `xorriso` ещё не скачаны.

### Команды

Выполняй из корня репозитория:

```text
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
python run.py
```

Сборка создаёт `build/xavieros.iso`. Скрипт запуска QEMU подключает постоянный 16-МиБ диск `data/xavieros-disk.img`, эмулирует Intel E1000 через user-mode NAT и задаёт виртуальным часам базу UTC. **Не запускай `python run.py --reset-disk`, если не хочешь удалить все файлы и аккаунты на виртуальном диске.**

## Команды консоли

Команды вводятся во встроенной оболочке XavierOS. Это не POSIX shell, и он не запускает команды Linux.

| Команда | Описание |
|---|---|
| `HELP`, `ABOUT`, `VERSION`, `BANNER` | Справка, информация о проекте, версия и логотип |
| `SYSINFO`, `INFO`, `CPU`, `MEM`, `PMM`, `HHDM`, `HEAP` | Сводка системы и памяти |
| `HEALTH`, `DIAG`, `SELFTEST`, `IDT`, `IRQ`, `UPTIME` | Диагностика и тесты ядра |
| `LS [PATH]`, `CAT PATH`, `STAT PATH`, `PWD`, `FSINFO`, `FSTEST` | Просмотр файлов и каталогов |
| `WRITE PATH TEXT`, `TOUCH PATH`, `MKDIR PATH`, `RM PATH`, `DF`, `FSCK`, `DISK` | Операции с диском и ФС (`FSCK` только проверяет метаданные и ничего не ремонтирует) |
| `USERADD`, `LOGIN`, `LOGOUT`, `WHOAMI`, `USERS`, `PASSWD`, `HOME` | Экспериментальная система пользователей |
| `NET`, `DHCP` | Состояние сети и настройка IPv4 |
| `PING HOST [COUNT]` | ICMP-проверка; от 1 до 8 запросов, по умолчанию 4 |
| `NETSTAT` | Сетевая конфигурация и счётчики E1000 |
| `NETCHECK` | Проверка E1000, линка, ARP шлюза и DNS-запроса к `example.com` |
| `HTTPGET http://HOST/PATH` | Получить небольшой ресурс по обычному HTTP и показать статус, заголовки и тело |
| `DATE`, `TIME`, `DATETIME`, `TIMEZONE`, `NTP [SERVER]` | Дата и время, ручной UTC-offset и синхронизация NTP |
| `CALC A OP B`, `ECHO TEXT`, `CLEAR`, `REBOOT`, `HALT` | Калькулятор, вывод текста, очистка, перезагрузка и остановка |

### Примеры сетевых команд

```text
NET
NETCHECK
NETSTAT
PING 10.0.2.2 1
PING example.com 4
HTTPGET http://neverssl.com/
NTP time.cloudflare.com
DATETIME
TIMEZONE +0300
```

`HTTPGET` пока поддерживает одно синхронное TCP-соединение с обычным HTTP. HTTPS/TLS, переходы по redirect, декодирование chunked transfer, большие загрузки, повторное использование TCP-соединений и универсальные TCP-приложения не реализованы. Буфер ответа ограничен; бинарные байты показываются точками и не исполняются как управляющие последовательности терминала.

## Важные ограничения

- XavierOS экспериментальна. Запускай её в QEMU или другой одноразовой виртуальной машине; работа на физическом оборудовании не проверена.
- Аккаунты не являются полноценной границей безопасности: команды работают в ring 0, изоляции процессов в пользовательском режиме нет. Не используй реальные или повторно используемые пароли.
- Сеть рассчитана на эмулируемую Intel E1000 и user-mode NAT в QEMU. DHCP, DNS A, ICMP, NTP и базовый HTTP/TCP экспериментальны. IPv6, TLS/HTTPS, повторная передача TCP, congestion control, физические сетевые адаптеры и IRQ-режим E1000 не реализованы.
- TCP-клиент минимальный и синхронный. У него есть ограниченные буферы и тайм-ауты, но это не полноценный TCP-стек общего назначения.
- NTP и часовой пояс не сохраняются после перезапуска. `TIMEZONE` принимает ручной фиксированный UTC-offset; автоматическое определение местоположения и правила перехода на летнее время не реализованы.
- XVDISKFS не использует журнал и не защищена от аварийного отключения питания. `FSCK` только проверяет метаданные и не восстанавливает файлы или прерванные записи. Делай резервные копии тестовых дисков.
- Планировщик кооперативный. Загрузчик ELF для пользовательских программ, изоляция виртуальных адресных пространств и графический рабочий стол не реализованы.

## Структура проекта

```text
XavierOS/
├── .cargo/             # Настройки bare-metal target и линковщика
├── src/                # Ядро, память, хранение, пользователи, время и сеть
├── tests/              # Тесты host-инструментов и регрессий
├── rootfs/             # Файлы для read-only initramfs XVRFS
├── Cargo.toml
├── build.py            # Сборка ядра и загрузочного ISO
├── run.py              # Запуск QEMU с постоянным диском и E1000 NAT
├── mkinitramfs.py      # Создание initramfs XVRFS
├── package_release.py  # Подготовка ISO и файла SHA-256
├── CHANGELOG.md
├── LICENSE
├── README.md
└── README.ru.md
```

Генерируемые `target/`, `build/`, `tools/`, `dist/` и локальный образ виртуального диска не являются исходным кодом и не должны попадать в репозиторий.

## Планы развития

Возможные следующие этапы: более полный TCP и HTTPS/TLS, постоянные системные настройки, лучшая изоляция процессов, сетевые прерывания, загрузчик пользовательских программ и в будущем графический рабочий стол. Это планы, а не возможности, обещанные в версии `0.1.6`.
