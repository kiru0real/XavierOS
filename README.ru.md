# XavierOS

**Небольшая экспериментальная хобби-операционная система x86_64 на Rust.**

Создана с нуля на `no_std`, загружается через Limine и в первую очередь тестируется в QEMU.

## О проекте

XavierOS — небольшая хобби-ОС для изучения загрузки компьютера и того, как ядро управляет памятью, устройствами, файлами, учётными записями и сетевыми пакетами. Ядро написано на Rust без стандартной библиотеки (`#![no_std]`) и предназначено для архитектуры `x86_64`.

После загрузки XavierOS открывает интерактивную консоль на framebuffer. Это экспериментальный проект ядра, а не настольная ОС, POSIX-среда или защищённая многопользовательская система.

## Текущие возможности

- **Bare-metal ядро на Rust** для `x86_64-unknown-none`, загружаемое через Limine.
- **Консоль на framebuffer** с собственным пиксельным логотипом XavierOS и редактируемой строкой ввода.
- **Клавиатура и прерывания:** PS/2, аппаратные прерывания PIC/PIT, обработчики исключений IDT и диагностика через serial.
- **Управление памятью:** разбор memory map от Limine, bitmap-аллокатор физических страниц (PMM), HHDM и небольшая куча ядра.
- **Хранение данных:** ATA PIO для primary IDE-диска QEMU, записываемая XVDISKFS, read-only initramfs XVRFS и небольшой VFS-диспетчер путей.
- **Прототип кооперативных задач** с переключением контекста. Это не вытесняющая многозадачность.
- **Локальные пользователи:** вход по паролю, выход, смена пароля, домашние каталоги, временная блокировка после неудачных входов и базовые ограничения путей на уровне shell.
- **Удобства оболочки:** история команд, Tab-дополнение команд и доступных путей, стрелки Left/Right, Home/End, Delete, Backspace, Ctrl+U и Ctrl+C.
- **Инструменты файловой системы:** `FSCK` выполняет проверку целостности без записи исправлений; `DF` показывает использование диска.
- **`SYSINFO` в стиле neofetch** с логотипом X и сведениями о ядре, CPU, экране, памяти, куче, диске, сессии и планировщике.
- **Экспериментальная сеть в QEMU:** эмулируемая Intel E1000, DMA-кольца RX/TX, передача Ethernet-кадров, ARP, статический IPv4, ICMP `PING` и DNS A-запросы.
- **Переносимые Python-скрипты сборки** для Windows, Linux и macOS, а также host-side тесты.

## Сборка и запуск

### Требования

- Rust через `rustup`.
- Python 3.10 или новее.
- QEMU с доступной для скрипта командой `qemu-system-x86_64`.
- На macOS/Linux: C-компилятор и `xorriso`. В Windows скрипты сборки могут подготовить поддерживаемые вспомогательные инструменты при необходимости.
- При первой сборке может понадобиться интернет для скачивания вспомогательных инструментов.

### Собрать ISO

Из корневой папки репозитория:

```sh
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
```

Загрузочный ISO появится в `build/xavieros.iso`.

### Запуск в QEMU

```sh
python run.py
```

Скрипт подключает постоянный виртуальный диск на 16 МиБ в `data/xavieros-disk.img` и эмулируемую сетевую карту Intel E1000 через QEMU user-mode networking. Чтобы стереть виртуальный диск вместе со всеми файлами и аккаунтами, выполни:

```sh
python run.py --reset-disk
```

**Внимание:** `--reset-disk` удаляет содержимое виртуального диска. Сделай резервную копию, если там есть нужные данные.

## Первый вход и пользователи

На новом виртуальном диске XavierOS запускается во временной сессии `live`. Создай первую постоянную учётную запись — она станет администратором:

```text
USERADD alice
LOGIN alice
WHOAMI
HOME
PASSWD
```

`USERADD` дважды запрашивает пароль и скрывает ввод. Пароль должен содержать 8–63 печатных ASCII-символа; регистр учитывается. Пароли хранятся как хэши PBKDF2-HMAC-SHA256 с солью. После трёх неудачных попыток вход временно ограничивается. Создание аккаунта и смена пароля требуют CPU-инструкции `RDRAND`; скрипт запуска QEMU использует `-cpu max`, чтобы она обычно была доступна в QEMU TCG. Поддерживается до восьми аккаунтов.

Обычные пользователи ограничены проверками оболочки и могут работать только в `/DISK/HOME/<name>`. Однако команды всё ещё исполняются в ring 0, поэтому это **не** полноценная изоляция пользовательских процессов и не надёжная граница безопасности. Не используй настоящие пароли или пароли, которые применяешь в других сервисах.

## Быстрый старт сети

Сетевой стек рассчитан на эмулируемую Intel E1000 и user-mode NAT в QEMU. По умолчанию используется профиль `10.0.2.15/24`, шлюз `10.0.2.2`, DNS `10.0.2.3`.

```text
NET
PING 10.0.2.2 1
PING 1.1.1.1 4
PING example.com 2
```

`PING <host> [count]` отправляет четыре запроса по умолчанию; количество можно задать от 1 до 8. Трафик проходит через QEMU и сеть хоста, поэтому результат ICMP зависит от настроек NAT, firewall и удалённого узла. QEMU может синтезировать или проксировать ответы, поэтому TTL не всегда соответствует конечному интернет-хосту.

DHCP, TCP, IPv6, физические сетевые карты и универсальные интернет-приложения пока не реализованы. Успешный `PING` не означает, что уже поддерживаются браузер или произвольные TCP-соединения.

## Команды консоли

Это небольшая собственная оболочка XavierOS, а не Bash или POSIX shell.

| Раздел | Команды | Назначение |
|---|---|---|
| Справка и информация | `HELP`, `ABOUT`, `BANNER`, `INFO`, `VERSION`, `SYSINFO` | Справка, сведения о проекте, версия и системная сводка в стиле neofetch |
| Оборудование и диагностика | `CPU`, `MEM`, `PMM`, `HHDM`, `HEAP`, `IRQ`, `IDT`, `DIAG`, `HEALTH`, `SELFTEST`, `UPTIME`, `TIME` | CPU, память, прерывания, таймер и диагностика подсистем |
| Файловая система | `DISK`, `DF`, `FSCK`, `LS`, `DIR`, `PWD`, `CAT`, `STAT`, `FSINFO`, `FSTEST`, `MKDIR`, `WRITE`, `TOUCH`, `RM` | Просмотр и управление файлами в поддерживаемых файловых системах |
| Аккаунты | `USERADD`, `USERS`, `LOGIN`, `LOGOUT`, `WHOAMI`, `PASSWD`, `HOME` | Локальные пользователи и сессии |
| Сеть | `NET`, `PING` | Информация об E1000 и проверка ICMP/DNS |
| Задачи и утилиты | `TASKS`, `TASKTEST`, `CALC`, `ECHO`, `CLEAR`, `REBOOT`, `HALT`, `TRAP` | Прототип задач, калькулятор, управление консолью и тест исключений |

`TIME` пока выводит счётчик тиков PIT и приблизительное время работы ядра; команда **не** читает реальные часы и не определяет местный часовой пояс. `FSCK` работает только на чтение и не чинит повреждённый диск. `TRAP` намеренно вызывает исключение CPU и останавливает ядро; запускай её только для проверки обработчиков исключений.

## Структура проекта

```text
XavierOS/
├── .cargo/                 # Цель bare-metal и флаги линковщика
├── src/                    # Ядро, память, прерывания, диски, пользователи, сеть
├── rootfs/                 # Файлы для read-only образа XVRFS
├── tests/                  # Host-side тесты инструментов сборки
├── .github/                # Шаблоны issues
├── Cargo.toml / Cargo.lock
├── limine.conf / linker.ld
├── setup.py / build.py / run.py
├── mkinitramfs.py / package_release.py
├── README.md / README.ru.md
├── CHANGELOG.md
└── LICENSE
```

Сгенерированные папки `target/`, `build/` и `tools/` не являются исходниками и не должны попадать в коммиты. Образ виртуального диска из `data/` — локальные данные; не добавляй его в Git.

## Статус и ограничения

XavierOS — **экспериментальная хобби-ОС**. Основная среда разработки и тестирования — QEMU; работа на физическом оборудовании не проверена. Пока нет рабочего стола, изоляции процессов в user mode, вытесняющего планировщика, отдельных адресных пространств, TCP, IPv6, DHCP и широкой поддержки оборудования. XVDISKFS не журналируется и не защищена от повреждения при сбое питания. Учётные записи и проверки файловой системы — прототипы, а не гарантии безопасности.

Запускай XavierOS в одноразовой виртуальной машине и сохраняй резервные копии дисков. Не используй её для конфиденциальных данных или рабочих нагрузок.
