# XavierOS

**Экспериментальная хобби-операционная система x86_64 на Rust.**

Ядро `no_std` загружается через Limine; есть framebuffer-рабочий стол, консоль, файловое хранилище и экспериментальная сеть.

## О проекте

XavierOS — учебная хобби-ОС на Rust без стандартной библиотеки, загружаемая через Limine. В версии 0.2.5 появился Renderer V2: программный RAM-backbuffer и копирование на физический framebuffer только изменённых тайлов 32×32. Добавлены общий PCI Bus Manager, список PCI-устройств и графическое приложение Device Manager (клавиша `D`); E1000 теперь использует результаты PCI-обнаружения. Для хранения по умолчанию используется современный VirtIO Block PCI с одной опрашиваемой split-очередью; ATA PIO сохранён как резервный вариант. Это всё ещё экспериментальное ядро: программная многослойная отрисовка не использует GPU, а VirtIO Block работает синхронно и без аппаратных прерываний.

## Возможности

- **Ядро и загрузка:** `x86_64-unknown-none`, Limine, IDT и обработчики исключений, PMM, HHDM, heap, PIC/PIT, PS/2-клавиатура и опрашиваемая PS/2-мышь.
- **Login Manager:** создание первой учётной записи администратора с подтверждением пароля, выбор аккаунта при запуске, вход с паролем, гостевая сессия `LIVE-USER` без пароля, блокировка/разблокировка, переключение пользователя и выход. Клавиатурные прерывания включаются до запуска экрана входа. Курсор мыши отображается и двигается через PS/2; выбор полей и управление экраном пока выполняются клавиатурой.
- **Renderer V2:** UI рисуется в RAM-backbuffer до 1366×768, а на экран отправляются только изменённые тайлы 32×32. Порядок рисования: обои, элементы рабочего стола, окна, оверлеи, курсор. Dirty-region для текста отмечается один раз на строку, а области Terminal и других подфреймбуферов обрезаются по собственным границам. Backbuffer использует обычные RAM-записи; итоговая передача в framebuffer — volatile-записи. Это программный рендерер без GPU, аппаратного page flipping и синхронизации с vblank.
- **Files:** открывается в домашней папке активной сессии (`/DISK/HOME/<username>` или `/DISK/HOME/live`), поддерживает переходы по папкам, историю Back и избранную папку на время сессии, Up/Home/Disk/System, страницы списка, ограниченный текстовый предпросмотр, создание папки/пустого файла и удаление на записываемом `/DISK`. Встроенный корень доступен только для чтения; полноценного редактора пока нет.
- **Terminal:** существующая оболочка внутри окна; редактирование строки, история команд, Tab completion, учётные записи, файловые команды, сетевые диагностики и отчёты. Открытый Terminal захватывает клавиатурный фокус и обновляет только изменившиеся строки, пока видимая история не прокручивается. Команда `CLEAR` полностью перерисовывает окно, убирая предыдущий вывод.
- **PCI / Device Manager:** перечисление PCI через Configuration Mechanism #1, BDF, Vendor/Device ID, Class и IRQ; чтение назначенных BAR; команды `PCI`, `DEVICES`, `DRIVERS`. E1000 использует общий PCI-список. Таблица хранит до 128 устройств.
- **Clock:** локальное время, фиксированное смещение от UTC, RTC и экспериментальная NTP-синхронизация.
- **Settings:** режимы 1024×768, 1280×720 и 1366×768 с запросом переключения через Bochs VBE, если адаптер поддерживает этот режим. Limine остаётся резервным способом выбрать разрешение при загрузке.
- **About:** вкладки обзора, ядра и лицензии.
- **Хранилище:** read-only XVRFS initramfs и записываемая XVDISKFS. По умолчанию QEMU подключает диск через современный VirtIO Block PCI; драйвер проверяет цепочку PCI capabilities и параметры notification, после чего использует одну опрашиваемую split-очередь и синхронный 512-байтовый I/O. ATA PIO можно выбрать через `python run.py --ata-disk`.
- **Инструменты:** Python-скрипты сборки, создания initramfs, запуска и упаковки релиза; host-side тесты.

## Сборка и запуск

Требуются Rust через `rustup`, Python 3.10+, QEMU (`qemu-system-x86_64`) и инструменты сборки образа, описанные в скрипте (в том числе `xorriso`/Limine, если они нужны системе).

```powershell
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
python run.py
```

ISO создаётся в `build/`. `run.py` подключает постоянный `data/xavieros-disk.img` как VirtIO Block PCI. Для проверки резервного ATA PIO используй `python run.py --ata-disk`; оба режима читают один и тот же raw-образ. Сделай резервную копию перед экспериментами. Не используй `--reset-disk`, если не собираешься пересоздать диск.

## Управление рабочим столом

- Мышь: Dock и элементы приложений, если доступно PS/2 auxiliary-устройство.
- Клавиатура: `F` Files, `T` Terminal, `N` Network, `C` Clock, `S` Settings, `A` About, `D` Device Manager, `X` системное меню. Стрелки перемещают выбор, Enter активирует, Escape закрывает окно или поднимается на уровень выше в Files. В Network клавиши `G` и `D` проверяют шлюз и DNS. В Clock клавиша `N` запускает NTP, `M`/`P` сдвигают часовой пояс на час, `S` сохраняет его.
- Files: нажми на папку для перехода; `BACK`/Backspace/`B` — история переходов, `UP`/Escape — родительский каталог; `PIN`/`P` закрепляет текущую папку, `FAVORITE`/`V` открывает её; `PREV`/`NEXT` переключают страницы; `NEW DIR` и `NEW FILE` создают элементы на `/DISK`; `DELETE` удаляет выбранный файл с `/DISK`. Вводи ASCII-имя и нажимай Enter; Escape отменяет создание.
- Terminal: команда `DESKTOP`, Escape или кнопка закрытия возвращает на рабочий стол.
- Системное меню: нажми `XAVIEROS` либо `X`; стрелками и Enter выбираются Desktop, Open Terminal, About, Lock Screen, Switch User, Log Out, Restart и Shut Down. Switch User и Log Out возвращают в Login Manager; Log Out сначала завершает текущую сессию и показывает сообщение о выходе. На экране входа используй `Up`/`Down` и Enter; пароль скрывается звёздочками. При первом запуске Tab или Enter переключают поля имени, пароля и подтверждения. В QEMU команда Shut Down отправляет запрос ACPI, после которого эмулятор может завершиться.
- Разрешение: выбери режим в Settings и нажми Apply Mode. Возможность переключения на лету зависит от VGA/Bochs VBE; альтернативные режимы доступны в Limine при загрузке.

## Команды оболочки

Введи `HELP` для полного списка. Основные группы: `SYSINFO`; `NET`, `NETSTAT`, `NETCHECK`, `PING`; экспериментальные `HTTPGET` и `FETCH`; `DATE`, `TIME`, `DATETIME`, `TIMEZONE`, `NTP`; `CONFIG`, `SETTINGS`, `REPORT`; `LS`, `CAT`, `STAT`, `WRITE`, `MKDIR`, `RM`, `DF`, `FSCK`; `USERADD`, `LOGIN`, `LOGOUT`, `WHOAMI`, `PASSWD`; диагностика `HEALTH`, `SELFTEST`, `TASKS`, `TASKRUN`, `TASKTEST`, `SCHEDSTAT`, `VMSTAT`, `VMTEST`, `KLOG`, `KERNEL`, `HEAP`, `MEM`, `PCI`, `DEVICES`, `DRIVERS`, `GFXINFO`, `GFXTEST`.

## Статус и ограничения

XavierOS — экспериментальная ОС, не предназначенная для защиты важных данных. Renderer V2 требует 32-битный framebuffer размером не более 1366×768; для неподдерживаемого режима используется прямой framebuffer. Это программный backbuffer с dirty tiles 32×32, а не GPU-композитор, набор независимых layer-surfaces или аппаратный page flip с vblank. PCI Manager использует старый Configuration Mechanism #1 и хранит максимум 128 устройств; настройка PCI bridges, MSI/MSI-X, PCIe extended capabilities и hotplug пока отсутствуют. VirtIO Block поддерживает modern PCI capabilities, одну split-очередь и синхронные опрашиваемые запросы по 512 байт; нет прерываний, multiqueue, packed rings и flush/discard negotiation. DMA ограничен адресами ниже 4 ГиБ. VirtIO Network, APIC/IOAPIC, USB xHCI и VirtIO-GPU пока не реализованы; обнаружение класса устройства не означает поддержку драйвером. Таблица TCB планировщика ограничена 16 слотами; каждый динамически выделяемый стек занимает 16 КиБ физически непрерывной памяти и пока не имеет guard page или обнаружения переполнения. Планирование остаётся кооперативным: PIT будит спящие задачи, но не вытесняет CPU-bound задачу, которая не вызывает yield. Переключатель контекста не сохраняет отдельное состояние FPU/SIMD. IRQ-safe spinlock защищает критические структуры на текущей однопроцессорной конфигурации, однако вся ОС ещё не SMP-safe. PMM управляет физическими страницами только ниже 4 ГиБ. VMM работает только с активным четырёхуровневым адресным пространством Limine и supervisor-страницами; пятиуровневый paging отклоняется, отдельные адресные пространства процессов, Ring 3, сборка таблиц страниц после unmap и SMP TLB shootdown отсутствуют. GUI аккаунтов, проверка пароля и ограничения путей оболочки — прототип, а не граница безопасности от произвольного кода ядра. Files поддерживает навигацию, ограниченный текстовый предпросмотр и несколько действий над `/DISK`, но не является полноценным файловым менеджером/редактором. Сеть ориентирована на E1000 и user-mode NAT QEMU; HTTPS/TLS, IPv6 и полноценные сетевые приложения не реализованы. XVDISKFS не журналируется и не гарантирует восстановление после аварийного отключения. Смена разрешения на лету зависит от VGA/Bochs VBE. Перезапуск и выключение ориентированы на эмулятор; выключение в QEMU зависит от поддержки ACPI, физическое оборудование не проверялось. Гостевая `LIVE-USER` не имеет пароля и может обращаться к своей записываемой домашней папке только через проверки путей оболочки. Автоматическая проверка GitHub Releases пока не реализована, поскольку для безопасного запроса необходим HTTPS/TLS.

**Запускай XavierOS в QEMU или другой одноразовой виртуальной машине. Не используй её для защиты важных данных.**
