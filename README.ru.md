# XavierOS

**Небольшая экспериментальная любительская ОС x86_64 на Rust.**

Создана с нуля на `no_std`, загружается через Limine и тестируется в QEMU.

## О проекте

XavierOS — небольшой проект операционной системы для изучения разработки ядра: загрузки компьютера, управления памятью, обработки ввода, хранения файлов и создания первых сетевых компонентов. Ядро нацелено на `x86_64` и написано на Rust без стандартной библиотеки (`#![no_std]`). Основная среда разработки и тестирования — QEMU; это не универсальная операционная система.

## Возможности

- **Ядро:** загрузка через Limine, framebuffer-консоль, serial-диагностика, обработчики исключений IDT, прерывания PIC/PIT и ввод с PS/2-клавиатуры.
- **Память:** карта памяти Limine, физический аллокатор страниц (PMM), HHDM, heap ядра и тесты памяти.
- **Хранение:** ATA PIO для виртуального диска QEMU, записываемая XVDISKFS, read-only initramfs XVRFS, VFS, команды `DF` и `FSCK` (только чтение).
- **Задачи:** прототип кооперативного планировщика и переключения контекста.
- **Локальные аккаунты:** экспериментальные пользователи, salted-хэши паролей PBKDF2-HMAC-SHA256, вход/выход и базовые ограничения доступа к домашним каталогам на уровне shell.
- **Интерактивная оболочка:** редактирование строки, история команд ↑/↓, Tab-автодополнение и neofetch-подобный экран `SYSINFO` с логотипом XavierOS.
- **Сеть в QEMU:** эмулируемая Intel E1000, DMA-кольца Ethernet, ARP, IPv4, ICMP `PING`, DNS A-запросы, DHCP-клиент и UDP-клиент NTP.
- **Системные часы:** `DATE`, `TIME`, `DATETIME`, `TIMEZONE` и `NTP`. `SYSINFO` не смешивает сводку системы с выводом часов.
- **Переносимые инструменты:** Python-скрипты сборки, тестирования, запуска, генерации initramfs и подготовки релиза для Windows, Linux и macOS при наличии нужных инструментов.

## Сборка и запуск

### Требования

- Rust toolchain, установленный через `rustup`.
- Python 3.10 или новее.
- QEMU с доступной командой `qemu-system-x86_64`.
- Инструменты для создания ISO с Limine. В macOS/Linux установите C-компилятор и `xorriso`; в Windows скрипты могут подготовить поддерживаемые вспомогательные инструменты.
- При первой сборке может понадобиться интернет для загрузки отсутствующих инструментов.

### Сборка и тесты

Выполняйте команды из корня репозитория:

```text
python setup.py
python -m unittest discover -s tests -v
python build.py --clean
python run.py
```

ISO создаётся в `build/xavieros.iso`. `run.py` запускает QEMU с эмулируемой Intel E1000 через user-mode networking и подключает постоянный виртуальный диск размером 16 МиБ: `data/xavieros-disk.img`.

**Внимание:** `python run.py --reset-disk` пересоздаёт виртуальный диск и безвозвратно удаляет хранящиеся на нём файлы и локальные аккаунты. Используйте этот параметр только если действительно хотите стереть диск.

После успешной сборки и проверки ISO подготовить файлы релиза можно командой:

```text
python package_release.py
```

Скрипт создаёт `dist/xavieros-0.1.5.iso` и `dist/SHA256SUMS.txt`.

## Команды оболочки

Команды вводятся во встроенной оболочке; это не POSIX shell, и она не запускает Linux-команды.

| Команда | Описание |
|---|---|
| `HELP`, `ABOUT`, `VERSION` | Справка, информация о проекте и версия |
| `SYSINFO`, `INFO`, `CPU`, `MEM`, `PMM`, `HHDM`, `HEAP`, `HEALTH`, `UPTIME` | Информация о системе и памяти; `SYSINFO` использует фирменный логотип XavierOS |
| `DIAG`, `SELFTEST`, `TASKS`, `TASKTEST`, `IDT`, `IRQ` | Диагностика ядра и подсистем |
| `LS`, `CAT`, `STAT`, `PWD`, `HOME` | Каталоги, чтение текстовых файлов, сведения о записях и текущем каталоге |
| `WRITE`, `TOUCH`, `MKDIR`, `RM`, `DF`, `FSCK`, `DISK`, `FSINFO`, `FORMAT DISK` | Операции с виртуальным диском и диагностика файловой системы (`FSCK` работает только на чтение; форматирование удаляет данные) |
| `USERADD`, `USERS`, `LOGIN`, `LOGOUT`, `WHOAMI`, `PASSWD` | Экспериментальное управление локальными аккаунтами |
| `NET`, `DHCP` | Состояние сети и запрос конфигурации DHCP |
| `PING 1.1.1.1 [COUNT]`, `PING example.com [COUNT]` | ICMP-запросы; необязательное число запросов от 1 до 8 |
| `DATE`, `TIME`, `DATETIME` | Дата и системное время |
| `TIMEZONE UTC`, `TIMEZONE +03:00`, `TIMEZONE +0300` | Ручное фиксированное смещение UTC; поддерживается компактная форма `±HHMM` |
| `NTP` или `NTP time.cloudflare.com` | Попытка синхронизировать системные часы через NTP |
| `ECHO TEXT`, `CLEAR`, `REBOOT`, `HALT` | Базовые команды оболочки и управления VM |

### Примечания о сети и часах

При запуске XavierOS пытается получить конфигурацию IPv4 по DHCP и использует резервный профиль QEMU, если аренду получить не удаётся. Сеть пока рассчитана на эмулируемую Intel E1000 и QEMU user-mode NAT. Часы изначально читаются из виртуального CMOS RTC (QEMU запускается с базовым временем UTC); затем время можно синхронизировать через NTP. Часовой пояс задаётся вручную фиксированным смещением — ОС не определяет местоположение пользователя и не содержит правил перехода на летнее время. Часовой пояс и синхронизация NTP не сохраняются между перезапусками.

## Структура проекта

```text
XavierOS/
├── .cargo/config.toml   # Bare-metal target и параметры линковщика
├── src/
│   ├── main.rs          # Точка входа ядра, framebuffer-консоль и shell
│   ├── memory.rs        # PMM, HHDM и диагностика памяти
│   ├── interrupts.rs    # IDT, исключения CPU, PIC/PIT
│   ├── heap.rs          # Heap-аллокатор ядра
│   ├── task.rs          # Кооперативные задачи и переключение контекста
│   ├── ata.rs           # Блочный ввод-вывод ATA PIO
│   ├── diskfs.rs        # Записываемая XVDISKFS
│   ├── fs.rs, vfs.rs    # Read-only initramfs и слой VFS
│   ├── users.rs         # Локальные аккаунты и пароли
│   ├── net.rs           # E1000, IPv4, ICMP, DNS, DHCP и NTP
│   └── clock.rs         # RTC, системные часы и часовой пояс
├── rootfs/              # Файлы, встраиваемые в read-only initramfs
├── tests/               # Host-side тесты инструментов и регрессии
├── setup.py             # Подготовка зависимостей сборки
├── build.py             # Компиляция ядра и создание ISO
├── run.py               # Запуск QEMU с диском и E1000
├── mkinitramfs.py       # Сборка образа initramfs XVRFS
├── package_release.py   # Версионированный ISO и SHA-256
├── Cargo.toml
├── Cargo.lock
├── limine.conf
├── linker.ld
├── LICENSE
├── CHANGELOG.md
└── README.md
```

Не добавляйте в Git сгенерированные каталоги `target/`, `build/`, `dist/`, `tools/`, кэши Python и `data/xavieros-disk.img`. Для этого бинарного проекта `Cargo.lock` следует хранить в репозитории.

## Дорожная карта

Возможные следующие этапы: повышение надёжности сети, сохранение часового пояса и настроек, расширенные инструменты проверки и восстановления файловой системы, более полный планировщик, изоляция виртуальных адресных пространств, пользовательские процессы и графический рабочий стол. Это цели развития, а не обещанные функции версии 0.1.5.

## Статус и ограничения

XavierOS — **экспериментальная любительская ОС**, а не универсальная или защищённая операционная система.

- Права аккаунтов проверяются оболочкой, при этом команды продолжают работать в ring 0. Полной изоляции процессов в User Mode нет; не используйте реальные или повторно используемые пароли.
- Сеть экспериментальная и рассчитана на Intel E1000 в QEMU и user-mode NAT. TCP, IPv6, сетевые прерывания и физические сетевые карты не реализованы.
- DHCP и NTP экспериментальны. Часовой пояс — фиксированное смещение UTC без автоматического определения местоположения и правил перехода на летнее время.
- XVDISKFS не имеет журнала и не защищена от аварийного выключения. `FSCK` проверяет метаданные, но не исправляет данные. Делайте резервные копии виртуальных дисков.
- Планировщик кооперативный. Пользовательские приложения, изолированные адресные пространства, рабочий стол и проверка на физическом оборудовании не реализованы.

Запускайте XavierOS в QEMU или другой одноразовой виртуальной машине. Не полагайтесь на неё для защиты конфиденциальных данных.
