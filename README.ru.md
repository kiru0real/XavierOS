# XavierOS

**Небольшая любительская операционная система для x86_64 на Rust.**

Самостоятельное ядро `no_std` с консолью на framebuffer, управлением памятью, диагностикой исключений CPU, обработкой клавиатурных прерываний, встроенной read-only файловой системой, постоянным виртуальным диском и прототипом кооперативного планировщика задач.

## О проекте

XavierOS — учебный проект для изучения загрузки компьютера, управления памятью, аппаратными событиями, файлами и задачами. Ядро написано на Rust без стандартной библиотеки (`#![no_std]`) и предназначено для цели `x86_64-unknown-none`. В качестве загрузчика используется Limine.

Эта версия загружается в текстовую консоль XavierOS, а не в графический рабочий стол. ОС предназначена для экспериментов в QEMU и других одноразовых виртуальных машинах, а не для повседневного использования или хранения важных данных.

## Возможности версии 0.1.0

- Самостоятельное ядро Rust с загрузкой через протокол Limine.
- Консоль на framebuffer и собственная командная оболочка.
- Разбор memory map Limine, Higher Half Direct Map (HHDM) и bitmap-аллокатор физических страниц (PMM) для доступной памяти ниже 4 ГиБ.
- First-fit heap ядра на непрерывных физических страницах.
- IDT x86_64 и диагностические обработчики исключений CPU, включая вывод регистров и CR2 при page fault.
- Переназначение legacy PIC 8259, таймер PIT на IRQ0, ввод с PS/2-клавиатуры через IRQ1 и ограниченный кольцевой буфер.
- Диагностика через последовательный порт COM1.
- Встроенная read-only файловая система XVRFS v1, создаваемая из `rootfs/` при сборке.
- Драйвер legacy ATA PIO для primary IDE master в QEMU.
- Записываемая XVDISKFS v1, смонтированная в `/DISK`, с операциями над файлами и каталогами на постоянном виртуальном диске размером 16 МиБ.
- Небольшой VFS-диспетчер для встроенной файловой системы и записываемого диска.
- Прототип кооперативного переключения контекста задач с отдельными стеками; вытесняющей многозадачности пока нет.
- Переносимые Python-скрипты настройки, сборки и запуска для Windows, macOS и Linux.

## Сборка и запуск

### Требования

- Python 3.10 или новее.
- Стабильный Rust toolchain с `rustup` и `cargo` ([rustup.rs](https://rustup.rs/)).
- QEMU с `qemu-system-x86_64` в `PATH`.
- `xorriso` в `PATH`; в Windows скрипт может загрузить готовый исполняемый файл при первой сборке.
- C-компилятор (`cc`, Clang или GCC) в macOS/Linux для сборки host-утилиты Limine.
- Доступ в интернет при первой сборке для загрузки официального binary-релиза Limine и, при необходимости, пакета `xorriso` для Windows.

Это требования к инструментам на основной ОС. Ядро не использует Python во время работы.

### 1. Установить Rust target

Из корня репозитория выполните:

```text
python setup.py
```

В некоторых системах вместо `python` используется `python3`.

### 2. Собрать загрузочный ISO

```text
python build.py --clean
```

Скрипт создаёт `build/xavieros.iso` и настроен на создание hybrid BIOS/UEFI-образа. Основное тестовое окружение — QEMU; работа на физическом оборудовании и со всеми реализациями прошивок не гарантируется.

### 3. Запустить в QEMU

```text
python run.py
```

При первом запуске создаётся пустой виртуальный диск размером 16 МиБ: `data/xavieros-disk.img`. Он сохраняется между запусками QEMU и чистыми сборками. Git игнорирует образ диска, чтобы не добавлять личные данные пользователя в репозиторий.

Сбросить диск (удалит все файлы в `/DISK`):

```text
python run.py --reset-disk
```

Запустить без записываемого диска:

```text
python run.py --no-disk
```

Драйвер хранения рассчитан на primary master контроллера legacy PC/PIIX IDE в QEMU. Используйте только одноразовый виртуальный образ, созданный проектом; не подключайте диск с важными данными.

### Инструменты для основной ОС

- **Windows:** установите Rust через rustup и QEMU с [официальной страницы загрузки](https://www.qemu.org/download/#windows). При первой сборке может автоматически загрузиться пакет `xorriso`.
- **macOS:** установите Rust, QEMU и xorriso; через Homebrew: `brew install qemu xorriso`.
- **Debian/Ubuntu:** установите Rust и выполните `sudo apt install qemu-system-x86 xorriso`.

Названия пакетов зависят от ОС. Python-скрипты заменяют инструменты сборки, привязанные к PowerShell, но внешние утилиты и поддерживаемое оборудование всё ещё имеют платформенные требования.

## Команды консоли

Команды вводятся заглавными ASCII-символами. Это собственная оболочка XavierOS, а не POSIX shell.

| Команда | Описание |
|---|---|
| `HELP` или `?` | Список команд |
| `ABOUT`, `INFO`, `VERSION` | Информация о проекте и версии (`0.1.0`) |
| `BANNER`, `SYSINFO`, `CPU` | Логотип, сводка системы и CPUID |
| `MEM`, `PMM`, `HHDM`, `HEAP` | Состояние подсистем памяти |
| `LS [PATH]`, `DIR [PATH]` | Список каталога (по умолчанию `/`) |
| `CAT PATH` | Вывести UTF-8 текстовый файл (буфер до 4 КиБ) |
| `STAT PATH` | Метаданные файла или каталога |
| `PWD` | Показать текущий каталог; смена каталога пока не реализована |
| `FSINFO`, `FSTEST` | Информация и проверки initramfs |
| `MKDIR /DISK/PATH` | Создать каталог на записываемом диске |
| `WRITE /DISK/PATH TEXT` | Записать текст в файл на диске |
| `TOUCH /DISK/PATH` | Создать пустой файл, не очищая существующий |
| `RM /DISK/PATH` | Удалить файл или пустой каталог |
| `DISK`, `DINFO` | Состояние диска и файловой системы |
| `FORMAT DISK` | Форматировать диск; команда разрушает данные |
| `TASKS` | Список кооперативных задач и счётчиков переключений |
| `TASKTEST` | Проверить кооперативное переключение контекста |
| `IDT` | Состояние IDT и обработчиков исключений |
| `IRQ`, `TIME` | Состояние прерываний, таймера и примерное время работы |
| `DIAG` | Краткая диагностика системы |
| `SELFTEST` | Проверки памяти, прерываний, ФС, метаданных диска и задач |
| `TRAP` | Намеренно вызвать invalid opcode; гостевая ОС остановится |
| `CALC A OP B` | Целочисленная арифметика с проверками (`+`, `-`, `*`, `/`) |
| `ECHO TEXT`, `CLEAR` | Вывод текста или очистка консоли |
| `REBOOT`, `HALT` | Перезагрузка или остановка гостевой ОС |

### Краткая проверка

```text
HELP
IDT
IRQ
TIME
LS /
CAT /ETC/ISSUE
LS /DISK
MKDIR /DISK/HOME
WRITE /DISK/HOME/HELLO.TXT Hello from XavierOS!
CAT /DISK/HOME/HELLO.TXT
DISK
TASKTEST
TASKS
FSINFO
FSTEST
SELFTEST
DIAG
```

Перезапустите QEMU и выполните `CAT /DISK/HOME/HELLO.TXT`, чтобы проверить сохранность данных. `TRAP` запускайте последней: команда намеренно вызывает фатальное исключение CPU и останавливает гостевую ОС.

## Структура проекта

```text
XavierOS/
├── .cargo/config.toml
├── src/main.rs          # Вход ядра, framebuffer, оболочка, клавиатура
├── src/memory.rs        # Карта памяти, HHDM, физический аллокатор страниц
├── src/interrupts.rs    # IDT, обработчики исключений, PIC/PIT и IRQ
├── src/heap.rs          # Heap ядра
├── src/fs.rs            # Чтение встроенной XVRFS
├── src/ata.rs           # Секторный ввод-вывод ATA PIO
├── src/diskfs.rs        # Записываемая XVDISKFS
├── src/vfs.rs           # VFS и маршрутизация путей
├── src/task.rs          # Контексты задач и прототип планировщика
├── rootfs/              # Файлы для initramfs
├── setup.py             # Установка bare-metal target Rust
├── mkinitramfs.py       # Сборка initramfs из rootfs/
├── build.py             # Сборка ядра и загрузочного ISO
├── run.py               # Запуск QEMU и подключение диска
├── limine.conf
├── linker.ld
├── Cargo.toml
├── Cargo.lock
├── LICENSE
├── CHANGELOG.md
├── XVRFS-FORMAT.md
└── XVDISKFS-FORMAT.md
```

Не добавляйте в репозиторий автоматически созданные каталоги `target/`, `build/` и `tools/`. Файл `Cargo.lock` нужно хранить в репозитории. Локальный образ диска `data/xavieros-disk.img` специально исключён из Git.

## Ограничения

XavierOS 0.1.0 — экспериментальная любительская ОС. Дисковая файловая система использует простой формат метаданных и непрерывных диапазонов и не защищена от сбоев; используйте только одноразовые виртуальные диски. ATA PIO работает синхронно и поддерживает текущую конфигурацию legacy IDE primary master в QEMU, а не произвольное оборудование хранения. Планировщик пока кооперативный: вытесняющей многозадачности, полноценного блокирующего планировщика, user mode и изоляции процессов нет. Нет сетевого стека и рабочего стола. Фатальные исключения CPU выводят диагностику и останавливают гостевую ОС. Heap — базовый first-fit аллокатор без стресс-тестирования. PMM управляет доступными физическими страницами ниже 4 ГиБ и не поддерживает SMP. Клавиатурный драйвер рассчитан на стандартный PS/2 и scancode Set 1; расширенные клавиши пока не поддерживаются.

Запускайте XavierOS только в QEMU или другой одноразовой виртуальной машине. Не используйте её на основном компьютере и не храните в ней важные данные. Совместимость с физическим оборудованием не подтверждена.
